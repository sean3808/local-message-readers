# local-message-readers

Lets a Local Agent read content from chat applications that would otherwise have to be copied and pasted by hand. Covers channels other than email (WeChat, LINE, Teams); email has its own project, see ADR-0003.

Read-only, local-first, existing tools first. Vocabulary is defined in `GLOSSARY.md`, settled decisions are in `docs/adr/`, and open work is in GitHub Issues.

The three READMEs (`README.md`, `README.zh-TW.md`, `README.zh-CN.md`) are updated together: same sections in the same order, so a change to one is made in all three.

## Public home

This repository is the public home of the project (ADR-0009). A bare `#NNN` in the docs that does not link to an issue refers to a ticket from the private era and cannot be resolved here. Issues, PRs and commits carry only fictional data: never put real conversations, names, account IDs or machine paths in them.

## Readers

In the commands below, `<repo>` is the folder where you cloned this repository. Inside `<repo>`, `uv run <reader> ...` runs the working tree: use it while developing and testing. Other projects call the installed snapshot by its bare name (`teams-reader ...`, `wechat-reader ...`), installed once with `uv tool install <repo>`. A snapshot holds the code of the moment it was installed, so other projects get a change when it is released: write the version's notes under `## [<x.y.z>]` in `CHANGELOG.md` (they become the GitHub Release notes), then from a clean `main` run `pwsh -File scripts/release.ps1 -Version <x.y.z>`, which waits for CI on the release commit, reinstalls the tool from it, and pushes the tag that publishes the GitHub Release (the script's help lists every step). Bump the minor version for a change that callers or the settings file must adapt to, the patch version otherwise. Install it non-editable: an editable install would run half-finished working-tree code against the archive (ADR-0011). Where the bare name is not installed, `uv run --project <repo> <reader> ...` runs the working tree from any folder.

- **WeChat**: `uv run wechat-reader conversations | messages <conversation> | search <keyword> [keyword ...] | recent --since <time> | download <message-id> --conversation <conversation> --to <dir> --time <time>` (`--help` lists the parameters). The reader does not remember a read position; the caller keeps the `--since` value for `recent`; pass back the last message's `time` unchanged (time inputs follow ADR-0010). `search` accepts one or more keywords (OR semantics, deduplicated), emits `keywords` (and `keyword` for a single keyword), and attaches `conversation_name`, `is_group`, and `matched_keywords` to each hit. Both `messages` and `search` keep the newest `--limit` rows (returned oldest to newest) and report `truncated`. Official accounts (ids starting with `gh_`, and the folded subscription/service placeholders) are excluded from `conversations`, `search` and `recent`. `wechat_exclude_conversations` in the settings file excludes chosen conversation ids from `recent` before `--limit` is applied, and `recent` always emits `excluded_messages` (the count in the `--since`..now range, `0` when empty or unset; `conversations`, `messages` and `search` are unaffected). After a WeChat upgrade, set `wechat = true` under `[smoke]` in the settings file (see Settings file), then run `uv run pytest tests/test_wechat_smoke.py`.
  - Media download (`download <message-id> --conversation <conversation> --to <dir> --time <time>`): take `id` and `time` from the same message in `messages`/`search`/`recent` output (about two thirds of `local_id` values collide across sharded message databases, so `--time`, parsed per ADR-0010, is the normal way to call). Deterministically resolves locally cached files (`local_type` base `49`, `appmsg/type == 6`), videos/thumbnails (`43`), and images (`3`, `md5` before `originsourcemd5`) via `hardlink/hardlink.db` decrypted into this run's temp directory. Strictly read-only toward the WeChat folder; rejects symlinks/reparse points and path traversal outside `<account>/msg/` or `--to`; verifies source stability (`stat` and `fstat` checked separately plus SHA-256) and uses exclusive create with ` (1)` suffixes so existing files are never overwritten. WeChat 4.x encrypted `.dat` images (`\x07\x08V1\x08\x07`, `\x07\x08V2\x08\x07`, or unrecognized bytes) report `status: "encrypted_unsupported"` without writing bytes to `--to`. As a safety net when `--time` is omitted: identical duplicate rows across databases are deduplicated, multiple distinct messages with the same `local_id` return `{"error": "...", "alternatives": [{"time", "timestamp", "type"}, ...]}` (sorted by `timestamp`, exit `1`), and any unreadable shard fails closed with `{"error": "...", "failures": [...]}` (exit `1`).
  - Download JSON contract: `{"conversation": {id, name, is_group}, "message_id": <int>, "message_type": "...", "items": [{"kind": "file|image|video|thumbnail|null", "status": "resolved|not_found|ambiguous|encrypted_unsupported|unsupported", "reason": "...", ...}], "failures": []}` (`name`, `path`, `size` are included only when `status == "resolved"`). Exit code is `0` iff at least one item is `resolved`; otherwise `1` (still printing the JSON above, or `{"error": "..."}` / `{"error": "...", "alternatives": [...]}` on argument/lookup/ambiguous-`local_id` errors). Reason codes: `resolved`, `hardlink_db_unavailable`, `no_md5_in_message`, `no_hardlink_row`, `file_missing`, `source_changed_during_copy`, `symlink_rejected`, `path_outside_msg_root`, `dir2id_unresolved`, `multiple_distinct_files`, `encrypted_or_unrecognized_image`, `unsupported_message_type`, `malformed_message_xml`.
  - Data freshness: the reader only reads data WeChat has already written on this computer. Messages from periods when the desktop app was off or logged out are not backfilled automatically; first sync chat history between the phone and the desktop app. The reader cannot tell whether the data is complete; before reading `recent`, compare against the time of the latest message on the phone.
  - Install: `uv sync`. The upstream is pinned to the commit of PR #22, see `[tool.uv.sources]` in `pyproject.toml`.
  - Key: with WeChat open, run once (PowerShell) `uv run wechat-cli init --db-dir "$env:USERPROFILE\Documents\xwechat_files\<wxid folder>\db_storage"`.

- **Teams**: `uv run teams-reader conversations | messages <conversation> | search <keyword> [keyword ...] | recent --since <time>` (`--help` lists the parameters). The reader maintains a local cumulative archive (ADR-0006); Teams does not need to be running, and the unread state is not changed. The caller keeps the `--since` value for `recent`; pass back the last message's `time` unchanged (time inputs follow ADR-0010). `search` accepts one or more keywords (OR semantics, deduplicated), emits `keywords` (and `keyword` for a single keyword), and attaches `conversation_name`, `is_group`, `matched_keywords`, and `hit_in_quote` to each hit. Both `messages` and `search` keep the newest `--limit` rows (returned oldest to newest) and report `truncated`. `teams_exclude_conversations` in the settings file excludes chosen conversation ids from `recent` before `--limit` is applied, and `recent` always emits `excluded_messages` (the count in the `--since`..now range, `0` when empty or unset; `conversations`, `messages`, `search` and `download` are unaffected).
  - Refresh: before answering, the reader merges the Teams cache into the archive, except when `--no-refresh` is passed or the throttle skips it. The throttle skips when the last clean refresh (it succeeded and reported no `failures`) of the same Teams profile is younger than `refresh_min_interval_seconds`: 120 when the key is not set in the settings file, `0` refreshes every time. `--refresh` forces a refresh, and passing both flags is a usage error. A skip sets `refresh.status` to `"skipped"` with `refresh.reason`. For multi-step investigations, pass `--refresh` once on the first query and `--no-refresh` on follow-up queries while citing that single `refresh.current_up_to`.
  - Same name: when every conversation matching a name is a 1:1 chat with exactly that current name and their `last_time` values all differ, the reader uses the newest one and lists the others in `alternatives` (`[{id, last_time}]`, newest first; also on a `download` error; absent when unambiguous). A `last_time` that is missing, blank, unparseable or has no offset is unknown: it sorts oldest, and two unknowns tie. Any group, any candidate matched only through an old name, or any tie returns an error listing each `id`; select by `id` instead.
  - Each message's `attachments` lists the attachment `name` and `url` (may be null). Download a message's attachments with `uv run teams-reader download <message-id> --to <dir>`; add `--name <file name>` to filter and `--conversation <name or id>` to disambiguate. An attachment without a link is reported as skipped; a failure returns a non-zero exit code and a JSON error. If a file name already exists, a suffix such as ` (1)` or ` (2)` is added and nothing is overwritten.
  - On the first download, a Microsoft device-code sign-in URL and code are shown on stderr. The credential is stored in `%LOCALAPPDATA%\local-message-readers\graph-token-cache.bin`, encrypted with DPAPI and bound to the Windows user. The `Files.Read.All` permission can read the entire personal OneDrive; delete the cache file to remove the local credential, or remove Microsoft Graph Command Line Tools under the Microsoft account privacy page (Apps and services) to revoke the grant.
  - One-time repair of old U+FFFD decoding damage: `uv run teams-reader repair-fffd` previews; after confirming, add `--write` to apply. It is limited to the default archive and requires a non-stale backup.
  - One-time rewrite of archived Chinese system-event texts (such as the old "member added" text) to the English text introduced in #39: `uv run teams-reader migrate-system-text` previews; after confirming, add `--write` to apply. It touches only rows of type `system` whose text is exactly an old description, keeps versions unchanged, is idempotent, and has the same default-archive and non-stale-backup guards as `repair-fffd`.
  - One-time removal of already-archived cache-only placeholder messages (`id = "-1"`): `uv run teams-reader clean-placeholder-messages` previews; after confirming, add `--write` to apply. It removes only `sources == ["cache"]` rows from `messages` and `cache_messages`, recalculates affected conversations' `last_message_time` / `last_message_timestamp`, is idempotent, and has the same default-archive and non-stale-backup guards as `repair-fffd`.
  - Data freshness: check `refresh.status` and `refresh.current_up_to` in the output (`null` when the cache was never synced successfully; the reason is in `refresh.current_up_to_reason`). `backup.stale` being true means no successful backup for more than 8 days, and the user must be told. History outside the cache window comes from importing the official export (`uv run teams-reader import-export <export file>`; an encrypted backup must exist before importing into the real archive).
  - Install: `uv sync`; no key is needed.
  - Own identity: the cache prefers `isSentByCurrentUser` and the export prefers `userId`. When the data lacks both, set `teams_self_id` in the settings file (see Settings file) to your Teams user ID (for example `8:example`); if the sender still cannot be determined, `is_self` is false.
  - The backup destination is required: set `backup_dest` in the settings file (see Settings file), or pass `--dest` (which wins over the settings file). Run manually with `uv run python -m readers.backup --dest <existing folder>`; when registering the schedule, pass `-Destination <existing folder>`.
  - Backup: the weekly encrypted backup contains the raw Teams and WeChat data; always check `wechat.ok` in the result. For backup and restore see `docs/teams-archive-backup.md`.

## Settings file

Personal settings (backup destination, own Teams identity, location of the commit blocklist, archive and profile paths, targets of the real-data smoke tests) all live in `%LOCALAPPDATA%\local-message-readers\settings.toml` (the same folder as the default archive); environment variables are not used for settings. Copy `settings.example.toml` there as `settings.toml` and fill in your own values; if you have an existing `settings.toml` in the repo root, move it there (the repo-root copy is no longer read, and `.gitignore` still ignores it so a stale copy is never committed). `settings.example.toml` is tracked and explains every key.

- Every entry point (`teams-reader`, `wechat-reader`, `python -m readers.backup`, `scripts/check_commit_blocklist.py`) accepts `--settings <file>` to read another settings file; no `settings.toml` means no value is set.
- Command-line parameters (`--archive-path`, `--profile-dir`, `--dest`) take precedence over the settings file.
- A misspelled key, a wrong type or a malformed file makes the command return an error naming the file and key; nothing is silently ignored.
- Tests always pass `--settings <tmp file>` (see `settings_args` / `use_settings` in `tests/conftest.py`), so they never read the real `settings.toml` or archive. The real-data smoke tests read only the `[smoke]` table and skip when it is absent.
- The only environment variables still read are system locations: `LOCALAPPDATA`, `USERPROFILE`, `ProgramFiles`.

## Commit blocklist

Install the hook with `uv tool run pre-commit install`. Set `commit_blocklist` in the settings file (see Settings file) to the private UTF-8 blocklist path before committing; missing or unreadable configuration blocks the commit. To scan the entire committed tree, run `uv run python scripts/check_commit_blocklist.py --head`. Hits are reported as `<path>:<line>`; a path that itself matches is shown as `<file #N, name withheld>`, where N is its position in `git diff --cached --name-only` (or `git ls-tree -r --full-tree HEAD` with `--head`), so the output never contains a blocked string.

If a blocklist entry is a substring of a string that is public (for example the owner's GitHub handle), list that string under `commit_blocklist_public` in the settings file (see Settings file): each case-insensitive occurrence is masked in file content and paths before matching, so the entry still matches everywhere else.

Verify the executable with `uv tool run pre-commit --version` before installation. Blocklist lines beginning with `# ` are comments; a leading backslash escapes an entry (including one beginning with `# ` or a backslash). Other non-empty lines are literal entries.
